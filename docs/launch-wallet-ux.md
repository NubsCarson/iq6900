# Wallet and confirmed-record UX

Rebased on master `e0166cd`, preserving hybrid `onStatus` progress/finalization observers, file/audio token selection, file notices, caption removal, and the merged board-rendering and exact-rent fixes. The previously published `7c13671` remains at `codex/iq8-published-review-20261005`. The launch registers its token on the IQ board before the final success screen. It uses the existing board-only EVM write for registration and the SDK 0.4.3 hybrid burner path for user inscriptions.

Previously approved wallets restore without a signature or network-switch prompt. Solana uses `connect({onlyIfTrusted:true})`; EVM checks the selected provider's accounts and current chain. Locked or unapproved wallets keep the Connect button. EVM account, disconnect and chain-change listeners are bound before the awaited RPC health check. Stale health or connection responses cannot restore a cleared session. Route changes remove listeners. No keys or signatures are persisted by the connection UI.

Once registration is confirmed, its signature prevents another paid registration in this tab. The known token is inserted into the existing markets list and notification runs without blocking the success screen. Notification failure does not turn a confirmed registration into a failed write. The next market refresh retains the current confirmed registration while the gateway catches up. No additional board scan or price enrichment is triggered by registration.

Confirmed inscriptions likewise remain visible in the current tab while the gateway index catches up. This bounded, chain-scoped list holds the 20 most recent confirmed writes. Each compose/retry operation retains its submitted author, chain, adapter and confirmed result. Retry reuses a confirmed signature; opening a fresh composition permits a new write with identical content. SDK success survives wallet invalidation because cleanup uses the captured signer. Late errors from an old wallet session cannot restore its retry checkpoint. Registration notification uses its submitted author as well. These records are not durable recovery across reloads.

Linked-coin buttons reuse the existing markets records and chart action. The gateway scan is bounded to 400 recent rows, so it does not establish universal coverage or creator verification. Existing market polling is unchanged. Launch errors distinguish token creation fees from metadata and network fees that may already have been paid.

Validation: `npm --prefix tests test` passes 60 tests using controlled providers, SDK writes and jsdom. The pending-operation regressions cover SDK success and failure after disconnect, disconnect during approval/write preflight, EVM account/chain/disconnect events during interactive and trusted RPC checks, author preservation, confirmed Retry, fresh identical compositions, and synchronous/asynchronous notification failures. Four additional cases execute captured-signer finalization after disconnect, resume only the remaining final transaction, display adapter stages, and retain upstream file/audio token selection and notices. Existing rent, funding/refund, untrusted-rendering and mixed-market regressions also pass. Earlier Chrome/mobile evidence predates this rebase; this local suite establishes no real-wallet signature or paid-launch acceptance.
