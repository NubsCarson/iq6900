# Robinhood wallet selection

Upstream now discovers EVM providers via EIP-6963 and automatically prioritizes Phantom. This candidate lets the user choose among the discovered wallets in a native dialog, including MetaMask, and offers Disconnect inside that dialog. Legacy injection is a fallback when no provider announces. Connection, health checks and signing all use the selected provider.

Only the successfully selected provider identifier is remembered. Silent restore uses `eth_accounts` and checks the current chain without requesting accounts or switching networks. Disconnect clears the app's signer, provider, burner and retry checkpoint, and prevents silent reconnection until explicit selection. It does not revoke the wallet extension's site permissions.

Before a hybrid inscription or board-only registration starts, the adapter checks that the selected account, network and submitted author still match. It snapshots the signer and wallet generation for the write. Upstream's progress observer, funding and sweep use that captured signer; observing SDK finalization does not add transactions. Disconnect during SDK submission preserves a successful result; a late failure cannot attach an old checkpoint to a new session. The page retains that result for Retry and clears the operation when a new composition opens. SDK 0.4.3 hybrid upload and deterministic burner funding remain upstream's implementation. The burner-funding balance check is not a guarantee that all later storage and gas costs are covered. Errors do not claim that an interrupted write spent nothing.

Validation: `npm --prefix tests test` passes 60 controlled regressions on the candidate rebased on master `e0166cd`. Wallet tests defer SDK, account approval and RPC promises to verify invalidation before and after submission. Progress tests execute both observed final transactions after disconnect and only the remaining transaction on resume. Page tests preserve confirmed author metadata, display adapter stages, and retain upstream file/audio token sources and file notices. Earlier Chrome and mobile QA predates this rebase and does not prove the current signing flow. No real-wallet signature, mainnet write, push or deployment was performed for this review.

I/O: wallet discovery uses browser events, not chain polling. The added pre-write account and chain checks go to the selected wallet. Existing burner funding reads and market polling remain unchanged. Board reads use the gateway.
